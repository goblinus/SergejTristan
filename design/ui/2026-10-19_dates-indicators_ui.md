# Индикация сроков дивидендной отсечки

Дата: 2026-10-19
Область: ui

Единые правила визуализации «приближения даты отсечки» для всех экранов (карточка собрания S1, строка сторожка S2, модал деталей S1.1). Источник токенов цвета — `2026-10-19_визуальный-стиль_ui.md`, реализация — компонент C-07 `DeadlineIndicator` из `2026-10-19_состав-ui-кита_ui.md`.

## 1. Источник статуса (контракт с backend)

Статус сторожка **вычисляется на сервере** (решение Р-3): фронтенд получает в ответе `GET /api/v1/watchlist` поля `status` и `days_to_cutoff` и **не реализует собственную логику порогов**. Каноническая шкала (решение Р-4) — ровно шесть идентификаторов, нижний регистр, без префиксов:

```
{ no_date, far, near, hot, critical, past }
```

Серверные правила (для понимания семантики; реализация — в `design/backend/2026-10-19_правила-расчёта-статуса-сторожка_backend.md`):

| Статус | Условие на сервере | Пороги |
|---|---|---|
| `critical` | отсечка сегодня (D = 0) | — |
| `hot` | 1 ≤ D ≤ T | T = `threshold_days` сторожка (персонально, по умолчанию 7, диапазон 1..365) |
| `near` | T < D ≤ 14 | граница 14 фиксирована конфигурацией (`DIVCAL_WATCH_SOON_DAYS`) |
| `far` | D > 14 | — |
| `past` | будущих отсечек нет, есть прошедшие | — |
| `no_date` | у тикера нет записей об отсечке | — |

Порядок проверки интервалов: `critical → hot → near → far`, что гарантирует корректность и при `T ≥ 14`.

## 2. Семантика зон для пользователя

| Зона | Семантика |
|---|---|
| `no_date` | ожидание информации, дата не объявлена |
| `far` | далёкий горизонт, наблюдение |
| `near` | пора планировать |
| `hot` | приближение в пределах порога сторожка — основной акцент (жёлтый) |
| `critical` | сегодня — последний день до закрытия реестра |
| `past` | событие завершено, новых данных нет |

## 3. Визуальное кодирование по зонам

| Зона | Цвет подложки чипа | Цвет текста/иконки | Иконка (Material Symbols Rounded) | Текст-подпись |
|---|---|---|---|---|
| `no_date` | `--neutral-chip` | `--on-surface-variant` | `event_busy` | «нет даты» |
| `far` | `--surface-3` | `--on-surface` | `schedule` | «N дн.» |
| `near` | `--primary-container` | `--on-primary-container` | `event_upcoming` | «N дн.» |
| `hot` | `--warn-container` | `--warn` | `warning` | «N дн.», «осталось N дн.» |
| `critical` | `--danger-container` | `--danger` | `priority_high` | «сегодня!» |
| `past` | `--surface-1` + граница `outline-variant` | `--on-surface-muted` / `--past` | `event_available` | «прошла» |

Примечания:
- Текст обязателен — статус не передаётся только цветом (доступность).
- Жёлтый (`--warn`) — единственный «сигнальный» цвет приближения; красный (`--danger`) резервируется для «сегодня» и ошибок, чтобы не смешивать семантику.
- Прошедшие события визуально приглушаются: строка/карточка на opacity 60%, чип — серый. Красный для «прошла» не используем: «прошла» — это факт, а не угроза.

## 4. Маппинг данных API → визуальные токены

Вход для компонента C-07 — пара `{ status, days_to_cutoff }` из ответа API:

| status | days_to_cutoff | Token set (chip) | Текст |
|---|---|---|---|
| `no_date` | `null` | neutral | «нет даты» |
| `far` | > 14 | subtle | «{days_to_cutoff} дн.» |
| `near` | T < N ≤ 14 | info | «{days_to_cutoff} дн.» |
| `hot` | 1 ≤ N ≤ T | warning | «осталось {days_to_cutoff} дн.» |
| `critical` | 0 | danger | «сегодня!» |
| `past` | `null` | muted | «прошла» |

Правила:
- Число дней фронтенд берёт из `days_to_cutoff` как есть, без собственного пересчёта от дат.
- Граница «горячей» зоны персональна (T из `threshold_days` сторожка): фронтенд не знает T и не обязан — сервер уже поместил сторожок в нужную зону. UI только отображает.
- **Карточка календаря S1** (собрание может не быть сторожком): локальная оценка зоны по `days_to_cutoff` с порогами по умолчанию (T=7, S=14) допустима для отображения, но как только тикер становится сторожком, источник истины — серверный `status`.

## 5. Формат текста по числу дней

- 1 день — «1 день», 2–4 — «N дня», 5–20 — «N дней», дальше по правилам русской плюрализации (21 день, 22 дня, 25 дней и т.д.).
- В `critical` дата совпадает с текущей — текст фиксированный «сегодня!» (без счётчика).
- `past`: подпись «прошла»; в tooltip (десктоп, hover) — последняя известная дата, если API её отдаёт; иначе без tooltip.

## 6. Поведение при отсутствии данных

- Дата отсечки неизвестна → зона `no_date`: нейтральный чип, в строке сторожка дата «не объявлена». При появлении даты (обновление данных) UI переключает зону по серверному статусу автоматически; подсветить изменение краткой анимацией (pulse 300 мс на чипе) при смене на `hot`/`critical`.
- Дата собрания известна, но отсечка не объявлена → чип `no_date` в карточке; в деталях собрания отдельная строка «Дата отсечки будет объявлена позже».
- Ошибка загрузки свежих данных дополняется баннером «данные могли устареть» поверх старого отображения (C-13); цвета зон не меняются. Метка «обновлено N минут назад» строится по полю `fetched_at` соответствующих записей (поле добавляется в API по решению Р-6); **при отсутствии `fetched_at` в ответе метка не отображается**.

## 7. Сортировка и приоритеты в списках

- S2 (сторожки): сверху `critical`, `hot`, `near`, `far` (по возрастанию дней внутри зоны), затем `no_date`, в конце — `past`.
- S1 (календарь): внутри выбранного периода сортировка по дате собрания; зоны влияют только на цвет чипа, не на порядок.

## 9. Снятые вопросы

В C-01 (AppBar) и C-02 (BottomNav) добавлен бейдж-счётчик сторожков в статусах `hot`/`critical`: нейтральная плашка `--warn-container`/`--warn`, скрыт при 0 и до первой загрузки списка сторожков; клиентского пересчёта нет — значение строится по серверным `status` из `GET /api/v1/watchlist`.

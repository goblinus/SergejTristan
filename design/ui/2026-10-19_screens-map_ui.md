# Карта экранов MVP

Дата: 2026-10-19
Область: ui

## Состав экранов

MVP ограничен двум основными экранами и одним контекстным представлением деталей.

| ID | Экран | Роут (предложение) | Назначение |
|---|---|---|---|
| S1 | Календарь собраний | `/` (или `/calendar`) | Обзор всех собраний с датами отсечек; точка входа приложения |
| S2 | Страница пользователя | `/me` | Управление сторожками: поиск тикеров, список, статусы сроков |
| S1.1 | Детали собрания (модально) | `/calendar?meeting=<id>` или drawer внутри S1 | Углубление по конкретному событию без потери контекста календаря |

Детали собрания в MVP не делаются отдельным полноценным экраном: достаточно модального окна/bottom-sheet внутри календаря. Это уменьшает сложность роутинга и соответствует объёму MVP.

## Структура App-уровня

```
AppShell (тёмная Material-тема)
├── AppBar
│   ├── Название: «Дивидендный календарь»
│   ├── Навигация: [Календарь] [Мои сторожки]
│   └── Справа: индикатор обновления данных, кнопка «Обновить»
├── RouterView
│   ├── S1 Календарь
│   │   ├── Панель фильтров (месяц, показ прошедших)
│   │   ├── Список/сетка карточек собраний
│   │   └── Детали собрания (modal/bottom-sheet) — S1.1
│   └── S2 Страница пользователя
│       ├── Панель «Найти тикер» (поле поиска + dropdown)
│       ├── Фильтры статусов сторожков
│       └── Список «Мои сторожки»
└── SnackbarHost (глобальные подтверждения/ошибки)
```

## Границы экранов

- **S1 владеет** данными календаря (собрания, даты отсечек, фильтры по месяцу). Не редактирует сторожки, но показывает значок «отслеживается» на карточках, чей тикер уже в сторожках (read-only индикация).
- **S2 владеет** сторожками (create/delete), читает справочник тикеров для поиска и актуальные даты событий для индикации (отсечка `dividend_payment`, а при её отсутствии — дата собрания с вопросом о дивидендах).
- **S1.1** — только чтение деталей конкретного собрания; открытие/закрытие не меняет состояние сторожков.

## Переходы

См. диаграмму `2026-10-19_navigation_ui.puml` (state-диаграмма). Кратко:

1. Старт приложения → S1.
2. S1 → S1.1 (клик по карточке собрания). S1.1 → S1 (закрытие).
3. S1 → S2 (вкладка «Мои сторожки» или CTA «Отслеживать» на карточке — переход с предзаполненным поиском).
4. S2 → S1 (вкладка «Календарь»; также переход по клику на тикер в сторожке с фокусом на соответствующем собрании, если оно есть).
5. Любой экран → баннер ошибки/офлайна (глобальное состояние, не меняет роут).

## Правила роутинга для фронтенда

- Роут `/` — редирект на `/calendar`.
- Параметр `?meeting=<id>` в `/calendar` управляет модальностью S1.1 (deep linking).
- Параметр `?ticker=<T>` на `/me` при открытии из календаря сразу фокусирует поле поиска с префиллом.
- Неизвестные роуты → 404-заглушка с ссылкой на `/calendar` (минимально для MVP).

## Что сознательно исключено из MVP

- Экраны регистрации/входа, настроек профиля.
- Отдельный экран «Карточка эмитента» с историей дивидендов.
- Экран администрирования источников данных.
- Центр уведомлений/push — за пределами MVP.

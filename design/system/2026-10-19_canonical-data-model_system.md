# 2026-10-19 — Каноническая ER-модель (system)

Обновлён: 2026-10-20 — добавлены дивидендные метрики: `dividend_period`, `dividend_per_share`, `last_price`, `dsi` (ADR-0005); добавлен `logo_url` (ADR-0006).
Обновлён: 2026-10-19 (ревью, раунд 2) — модель приведена к решению Р-2 протокола ревью раунда 1: таблица `record_dates` (вместо `record_cutoffs`) с прямой связью `ticker_id`, опциональным `meeting_id` и колонкой `kind`; таблица `watchlist_items` (вместо `watchers`); состав колонок синхронизирован со схемой БД backend.

## Назначение документа

Единый словарь сущностей и каноническая модель данных MVP. Источник истины для:
- backend-области — при проектировании схемы БД (SQLAlchemy-модели, миграции);
- frontend-области — при определении TypeScript-типов и DTO.

ER-диаграмма: [2026-10-19_er-модель_system.puml](./2026-10-19_er-модель_system.puml).

## Общие соглашения

- **Даты отсечки, собраний** — календарная дата без времени (тип `DATE`), в семантике московского времени (UTC+3). Хранятся как `DATE`, сериализуются в ISO 8601 (`YYYY-MM-DD`). Часовой пояс в значении не кодируется.
- **Технические метки времени** (`fetched_at`, `created_at`) — тип `TIMESTAMP` в UTC (ISO 8601 с `Z`), заполняются системой.
- **Поля трассировки** (`source_url`, `fetched_at`) — во всех таблицах доменных данных (все, кроме `watchlist_items`); см. ADR-0003.
- **Идентификаторы** — суррогатный целочисленный PK (`id`) у всех сущностей. Бизнес-ключи отражены уникальными ограничениями ниже (используются для upsert).
- Именование полей — английские snake_case термины из глоссария. Обязательность полей отмечена `NOT NULL`.

## Сущности

### 1. Тикер (`tickers`)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | INTEGER PK | да | Суррогатный ключ |
| `ticker` | VARCHAR(16) | да | Торговый код на Мосбирже (SECID: SBER, GAZP…). **Бизнес-ключ, UNIQUE** |
| `short_name` | VARCHAR(255) | да | Краткое наименование бумаги с MOEX |
| `full_name` | VARCHAR(512) | нет | Полное наименование эмитента, если известно |
| `isin` | VARCHAR(12) | нет | ISIN — вспомогательный идентификатор для связывания источников |
| `board` | VARCHAR(16) | нет | Режим торгов (например, `TQBR`). Информационно |
| `lot_size` | INTEGER | нет | Размер лота. Информационно |
| `logo_url` | VARCHAR(512) | нет | URL или относительный путь к логотипу эмитента; NULL — логотип не задан (UI показывает монограмму). MVP — курируемые локальные SVG (ADR-0006) |
| `last_price` | NUMERIC(18,4) | нет | Последняя цена акции, ₽ (MOEX ISS). Техническое поле для расчёта доходности |
| `price_updated_at` | TIMESTAMP(UTC) | нет | Момент последней загрузки цены |
| `dsi` | SMALLINT 0..100 | нет | Индекс стабильности дивидендов — материализованный снапшот ADR-0005, пересчитывается скриптом сбора |
| `dsi_updated_at` | TIMESTAMP(UTC) | нет | Момент последнего расчёта DSI |
| `is_active` | BOOLEAN | да (DEFAULT TRUE) | FALSE — бумага исчезла из листинга (снятие с торгов); записи не удаляются |
| `source_url` | TEXT | да | URL запроса к источнику (например, эндпоинт MOEX ISS) |
| `fetched_at` | TIMESTAMP(UTC) | да | Время последней успешной загрузки записи из источника |

### 2. Собрание акционеров (`shareholder_meetings`)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | INTEGER PK | да | Суррогатный ключ |
| `ticker_id` | INTEGER FK -> tickers.id | да | Эмитент (обязательная связь) |
| `meeting_date` | DATE | да | Дата проведения собрания |
| `meeting_type` | VARCHAR(16) | да | Тип собрания: `annual` (годовое) / `extraordinary` (внеочередное); перечень контролируется кодом |
| `dividend_question` | BOOLEAN | да (DEFAULT TRUE) | В повестке есть вопрос о выплате дивидендов (для MVP всегда `true` — отсев на этапе сбора; поле оставлено для явности контракта) |
| `dividend_period` | VARCHAR(16) | нет | Период выплаты: `year` / `half_year` / `quarter` (NULL — не раскрыт) |
| `dividend_per_share` | NUMERIC(12,4) | нет | Сумма на одну акцию, ₽ (NULL — не раскрыта; ≥ 0) |
| `description` | TEXT | нет | Формулировка вопроса повестки из источника |
| `source_url` | TEXT | да | Ссылка на сообщение о собрании в источнике — трассировка (ADR-0003); отдаётся наружу в DTO (Р-6) |
| `fetched_at` | TIMESTAMP(UTC) | да | Время загрузки; отдаётся наружу в DTO (Р-6) |

**Бизнес-ключ (UNIQUE):** `(ticker_id, meeting_date, meeting_type)` — одно собрание одного типа эмитента в день.

### 3. Дата отсечки / закрытия реестра (`record_dates`)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | INTEGER PK | да | Суррогатный ключ |
| `ticker_id` | INTEGER FK -> tickers.id | да | Эмитент (обязательная связь) |
| `meeting_id` | INTEGER FK -> shareholder_meetings.id | нет | Связанное собрание, если установлена источником/эвристикой связывания. NULL допустим: дата отсечки может быть собрана без связи с конкретным собранием. ON DELETE SET NULL |
| `record_date` | DATE | да | Дата закрытия реестра (дата отсечки) |
| `kind` | VARCHAR(32) | да (DEFAULT `dividend_payment`) | Вид отсечки: `dividend_payment` — для выплаты дивидендов; `meeting_participation` — для участия в собрании. Сторожки отслеживают только `dividend_payment` |
| `source_url` | TEXT | да | Ссылка на сообщение/страницу источника |
| `fetched_at` | TIMESTAMP(UTC) | да | Время загрузки; отдаётся наружу в DTO (Р-6) |

**Бизнес-ключ (UNIQUE):** `(ticker_id, record_date, kind)` — дедупликация и upsert.

Допущение «одно собрание — не более одна отсечка» отменено (Р-2): связь собрания и отсечек — `1 : 0..N`, отсечка может существовать без собрания (`meeting_id IS NULL`) — такие записи обязаны отображаться в календаре (фронтенд читает `GET /api/v1/record-dates`).

### 4. Сторожок (`watchlist_items`)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | INTEGER PK | да | Суррогатный ключ |
| `ticker_id` | INTEGER FK -> tickers.id | да | Отслеживаемый тикер. **Бизнес-ключ, UNIQUE** — один сторожок на тикер (однопользовательская система) |
| `threshold_days` | INTEGER | да (DEFAULT 7) | Индивидуальный порог зоны `hot` статуса сторожка, в календарных днях (1..365) |
| `created_at` | TIMESTAMP(UTC) | да | Момент добавления в отслеживание |

Полей `source_url`/`fetched_at` нет: сущность пользовательская, пишется только API, внешнего источника нет.

Целевая дата отсечки **не хранится** в сторожке: она вычисляется динамически как ближайшая будущая `record_date` (`kind = dividend_payment`) по связи `watchlist_items.ticker_id -> record_dates`. Это устраняет рассинхрон при появлении новой отсечки — сторожок всегда «смотрит» на актуальную ближайшую дату. Статус (каноническая шкала `no_date/far/near/hot/critical/past`) — производное, **вычисляется в API на чтении** (Р-3/Р-4), в БД не хранится; правила — в `design/backend/2026-10-19_правила-расчёта-статуса-сторожка_backend.md`. `next_meeting_date` в DTO — тоже производное: дата собрания, связанного с `next_record_date` через `record_dates.meeting_id`; в БД не хранится.

## Дивидендные метрики (ADR-0005)

- **Период и сумма на акцию** — атрибуты собрания (`dividend_period`, `dividend_per_share`); nullable, поскольку источник может раскрыть не всё.
- **Дивидендная доходность** (`yield_percent`) — производная на чтении: `dividend_per_share / tickers.last_price × 100`, округление до 0.1. В БД не хранится; в DTO входит в объект `dividend`.
- **DSI** — производная от 5-летней истории выплат, материализуется в `tickers.dsi` (0–100) и `dsi_updated_at`; формула и ограничения — [ADR-0005](./adr/2026-10-20_adr-0005-dividend-metrics_system.md) и [backend-спецификация](../backend/2026-10-20_dividend-metrics_backend.md). На чтении не пересчитывается.
- Полная история выплат в БД MVP не хранится; это осознанное ограничение, а не пропуск модели.

## Связи и кардинальности

- `tickers 1 -- N shareholder_meetings` — у эмитента может быть много собраний; собрание обязательно принадлежит эмитенту.
- `tickers 1 -- N record_dates` — у эмитента может быть много дат отсечки.
- `shareholder_meetings 1 -- 0..N record_dates` — опциональная связь; отсечка может быть без собрания (`meeting_id IS NULL`, ON DELETE SET NULL).
- `tickers 1 -- 0..1 watchlist_items` — один сторожок на тикер; тикер без сторожка — норма.

## Замечания по целостности

- Удаление доменных записей в MVP не предусмотрено: исчезновение тикера из листинга фиксируется `is_active = FALSE` (soft-деактивация в скриптах сбора); история собраний/отсечек сохраняется.
- Доменные FK — `ON DELETE RESTRICT` (страховка от случайного каскадного удаления истории); `record_dates.meeting_id` — `ON DELETE SET NULL`.

## Маппинг на типы

- БД: SQLAlchemy — `Date` (без tz) для доменных дат; `DateTime(timezone=True)` для технических меток UTC.
- API/DTO (Pydantic): `date` -> строка `YYYY-MM-DD`; `datetime` -> ISO 8601 c `Z`.
- Frontend (TypeScript): доменные даты — `string` формата `YYYY-MM-DD`; статус сторожка — готовое значение из API; `DividendTerms` (`period`, `amount_per_share`, `yield_percent`) и `dsi` — готовые значения, без клиентского пересчёта.

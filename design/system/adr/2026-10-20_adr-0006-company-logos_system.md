# ADR-0006: Логотипы эмитентов и компактная строка фактов

- Дата: 2026-10-20
- Статус: Принято (решение владельца)
- Контекст: область system, MVP «Дивидендный календарь»

## Контекст и проблема

Владелец запросил два изменения карточки компании и строки сторожка:

1. добавить логотип компании рядом с тикером и названием;
2. разместить дату собрания и дату отсечки на одном уровне с выплатами за период, суммой на акцию и доходностью.

Ранее карточка показывала метрики отдельным блоком, а даты — двумя строками ниже. Нужно определить: откуда берутся логотипы, где они хранятся, как отдаются в API и как выглядит новая компоновка на десктопе и мобильном.

## Рассмотренные варианты

### A. Хотлинк на сайты эмитентов / внешний CDN

- (+) Не нужно хранить файлы.
- (−) Ненадёжно: блокировки, смена URL, разные размеры и лицензии; офлайн-прототип не работает.

### B. Логотипы только во фронтенде по соглашению `/logos/{ticker}.svg`

- (+) Ноль изменений в БД и API.
- (−) Логотип — атрибут эмитента, а не фронтенда; другой клиент не получит его; нет управления отсутствием/заменой.

### C. Курируемый `tickers.logo_url` + локальные статические файлы (выбран)

- В БД хранится `logo_url` (относительный путь или https).
- Для MVP — локальные SVG в статике бэкенда (`/static/logos/{TICKER}.svg`), курируемые вручную; внешние сайты не скрапятся и не хотлинкаются.
- API отдаёт `logo_url` в `Ticker`, `Meeting`, `WatchlistItem`.
- Фронтенд при `null` или ошибке загрузки показывает монограмму (1–2 буквы тикера).

- (+) Работает офлайн, предсказуемо, без внешних зависимостей.
- (+) Поле данных явное; логотип можно заменить без изменения кода.
- (−) Нужна ручная кураторская работа по набору логотипов; в MVP допустимо частичное покрытие.

## Решение

Принят **вариант C**. Дополнительно фиксируется компоновка:

### Логотип

- Размер 32×32 в карточке и строке, 36×36 в модале; скругление 8–9 px, `object-fit: contain`.
- Логотип декоративный (`alt=""`), так как рядом всегда есть название компании.
- Fallback: монограмма из первой буквы тикера на `--surface-3`; показывается, если `logo_url` пуст или файл не загрузился.
- Источник в MVP — курируемый набор SVG; скрипт `sync_logos.py` проставляет `logo_url` и копирует файлы в статику. Внешние логотипы не хотлинкаются.

### Строка фактов

Один блок из пяти ячеек в одну строку:

| Ячейка | Значение |
|---|---|
| Период | `год` / `полгода` / `квартал` |
| На акцию | `33,30 ₽` |
| Доходность | `8,4%` |
| Собрание | `12.11.2026` |
| Отсечка | `09.11.2026` |

Порядок в карточке S1: логотип + тикер + название → строка фактов → индикатор срока + DSI (DSI последним).
Порядок в строке S2: логотип + тикер + название + «Снять» → строка фактов → индикатор срока + DSI.
Мобильная ширина сохраняет пять колонок с уменьшенной типографикой; переносы дат не допускаются.

## Последствия

- Схема: `tickers.logo_url VARCHAR(512) NULL`; API: `logo_url` в трёх DTO.
- UI: новый компонент `CompanyIdentity` (логотип + имя) и `CompanyFacts` (5 ячеек) вместо раздельных блоков метрик и дат.
- Логотипы — курируемые ассеты; при отсутствии показывается монограмма, интерфейс не ломается.
- Товарные знаки остаются собственностью эмитентов; в MVP используются только для идентификации в демонстрационном интерфейсе.

## Затронутые артефакты

- System: каноническая модель, ER-диаграмма, обзор архитектуры.
- Backend: схема БД, API-контракт, скрипты сбора, архитектура.
- Frontend: типы DTO, компонентная схема, архитектура, спецификация метрик.
- UI: вайрфреймы, UI-кит, спецификация метрик (синхронизация макета).

## Проверка соответствия

- [x] `logo_url` есть в БД и API.
- [x] Логотип отображается в S1, S2 и S1.1.
- [x] Даты и метрики — в одной строке из пяти ячеек.
- [x] DSI остаётся последним элементом.
- [x] Предусмотрен fallback без логотипа.

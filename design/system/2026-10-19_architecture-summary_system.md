# 2026-10-19 — Обзор архитектуры (system)

## Назначение документа

Верхнеуровневый обзор архитектуры MVP «Дивидендный календарь»: состав компонентов, их взаимодействие на уровне системного контекста, границы MVP. Документ — отправная точка для детальных спецификаций областей `ui`, `frontend`, `backend`.

## Контекст системы

См. диаграмму: [2026-10-19_контекст-системы_system.puml](./2026-10-19_контекст-системы_system.puml).

### Участники и компоненты

| Участник | Тип | Описание |
|---|---|---|
| Пользователь (User) | Актор | Единственный пользователь — владелец системы. Просматривает календарь и список тикеров, настраивает «сторожки». |
| Фронтенд (Frontend SPA) | Внутр. система | Одностраничное приложение на Vue.js 3 (Composition API), тёмная Material-тема. Взаимодействует с бэкендом по REST API. |
| Бэкенд (Backend API) | Внутр. система | REST API на Python (фреймворк — см. ADR-0002). Только читает доменные данные из БД; пишет только сущность «Сторожок». |
| База данных (Database) | Внутр. система | Реляционная БД (выбор СУБД — см. ADR-0001). Хранит тикеры, собрания, даты отсечки, сторожки. |
| Скрипты сбора (Data collectors) | Внутр. система | Набор офлайн-скриптов на Python: извлечение данных из официальных источников, нормализация, запись в БД (upsert, идемпотентность — см. ADR-0003). |
| moex.com (MOEX ISS) | Внешняя система | Московская биржа: список тикеров, календарь дивидендных событий. |
| disclosure.ru | Внешняя система | Центр раскрытия корпоративной информации: решения о собраниях акционеров, даты закрытия реестра. |
| Прочие источники | Внешняя система | Резерв: e-disclosure.ru, сайты эмитентов. Расширяемый список. |

### Ключевые взаимодействия

1. Пользователь -> Фронтенд: просмотр календаря/тикеров, управление сторожками (выбор тикеров для отслеживания).
2. Фронтенд -> Бэкенд: REST API по HTTP/JSON (read-only по доменным данным + CRUD по сторожкам).
3. Бэкенд -> БД: чтение тикеров/собраний/дат отсечки; чтение и запись сторожков.
4. Скрипты сбора -> Внешние источники: извлечение сырых данных (парсинг HTML/CSV/API источников).
5. Скрипты сбора -> БД: нормализованная запись (upsert) тикеров, собраний, дат отсечки. Скрипты являются **единственным писателем** доменных данных.
6. Бэкенд не обращается к внешним источникам; фронтенд не обращается к БД напрямую.

## Границы MVP

### Входит в MVP (in scope)

- Список тикеров Московской биржи (акции российских эмитентов).
- Календарь собраний акционеров, на повестке которых — вопрос о выплате дивидендов.
- Хранение дат дивидендной отсечки (дата закрытия реестра), связанных с собраниями.
- «Сторожок»: выбор тикеров пользователем, отображение приближения даты отсечки.
- Страница пользователя: управление списком отслеживаемых тикеров.
- Офлайн-обновление данных скриптами (запуск вручную или по расписанию ОС — cron/Task Scheduler).

### Не входит в MVP (out of scope)

- **Авторизация и аутентификация** — система однопользовательская, слой безопасности отсутствует.
- **Уведомления** (e-mail, push, Telegram) — «сторожок» только визуализирует близость даты в интерфейсе.
- **Мультипользовательность** — один пользователь, один набор сторожков.
- **Деплой и инфраструктура** — локальный запуск; CI/CD, контейнеризация, мониторинг вне рамок.
- **Расчёт размера дивидендов и дивидендной доходности** — храним только даты событий, суммы не моделируются.
- **Портфель пользователя** (учёт позиций, брокерские интеграции) — не рассматривается.
- **Облигации, иностранные бумаги** — только акции Мосбиржи.
- **Исторические архивы** — хранится актуальный срез + ближайшие события; глубокая история не требуется.

## Допущения и ограничения

- Даты дивидендной отсечки интерпретируются как календарные даты без времени (московское время, UTC+3 — см. глоссарий).
- Источники данных не предоставляют гарантий SLA: скрипты должны быть устойчивы к изменению вёрстки/форматов; сбои источника не блокируют работу фронтенда (данные остаются последними успешно загруженными).
- Один пользователь, одна машина: конкурентный доступ к БД минимален, транзакционная модель простая.

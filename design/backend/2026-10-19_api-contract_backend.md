# 2026-10-19 — API-контракт (backend)

## Назначение документа

REST API MVP «Дивидендный календарь» — контракт, по которому фронтенд пишет типы и HTTP-клиент. Реализация: FastAPI по ADR-0002; схемы — Pydantic v2.

## Общие правила

- **Базовый префикс и версионирование**: все эндпоинты под `/api/v1`. Следующая несовместимая версия — `/api/v2` (вне MVP).
- **Формат**: JSON (`application/json; charset=utf-8`), кодировка UTF-8.
- **Даты**: ISO 8601 даты без времени — `YYYY-MM-DD` (тип Pydantic `date`). Метки времени — ISO 8601 с зоной UTC: `YYYY-MM-DDTHH:MM:SSZ` (`datetime` c `timezone.utc`). Календарные даты домена — московское время UTC+3, см. глоссарий system.
- **Идентификация тикера в путях** — по SECID (`/tickers/SBER`), регистр незначим, нормализуется к верхнему.
- **Аутентификация отсутствует** (однопользовательский MVP).
- **Пагинация** (эндпоинты списков): query `page` (>=1, по умолчанию 1) и `page_size` (1..100, по умолчанию 50). Ответ — конверт `Page`, см. ниже.
- **Read-only доменные данные**: GET-эндпоинты не изменяют состояние. Изменения — только в `/watchlist`.

## Формат ошибок

Ошибки — в формате FastAPI по умолчанию (совместим с простым RFC 7807-подобным конвертом):

```json
{ "detail": "ticker not found" }
```

Ошибки валидации запроса — 422 с массивом `detail` (стандартный формат FastAPI/Pydantic: `loc`, `msg`, `type`).

| HTTP-код | Когда |
|---|---|
| 200 | Успешное чтение; идемпотентный повторный POST /watchlist (уже существующий сторожок). |
| 201 | Создан новый сторожок (POST /watchlist). |
| 204 | Сторожок удалён (DELETE /watchlist/{ticker}). Тело отсутствует. |
| 404 | Тикер не найден; сторожок не найден. |
| 422 | Невалидные параметры запроса/тела (автовалидация Pydantic). |
| 500 | Внутренняя ошибка. |

Семантика POST /watchlist идемпотентна: повторный вызов с существующим тикером не создаёт дубль и возвращает 200 с текущим объектом (обновляя `threshold_days`, если передан).

## Схемы (Pydantic)

Имена полей — `snake_case`, как в JSON ниже.

### Page (конверт пагинации)

```json
{
  "items": [ /* ... */ ],
  "page": 1,
  "page_size": 50,
  "total": 137
}
```

### Ticker

```json
{
  "ticker": "SBER",
  "short_name": "Сбербанк",
  "full_name": "Сбербанк России ПАО ао",
  "isin": "RU0009029540",
  "board": "TQBR",
  "lot_size": 10,
  "logo_url": "/static/logos/SBER.svg",
  "is_active": true,
  "fetched_at": "2026-10-19T06:00:00Z"
}
```

Поля `full_name`, `isin`, `board`, `lot_size`, `logo_url` допускают `null`. `logo_url` — относительный путь или https-URL логотипа эмитента (ADR-0006); при `null` фронтенд показывает монограмму. `fetched_at` (момент последнего успешного сбора записи) отдаётся наружу (решение system Р-6) — фронтенд показывает индикатор свежести «обновлено N минут назад». `source_url` тикера наружу не отдаётся (техническое поле трассировки).

### RecordDate

```json
{
  "ticker": "SBER",
  "record_date": "2026-07-10",
  "kind": "dividend_payment",
  "meeting_id": 42,
  "fetched_at": "2026-10-19T06:00:00Z"
}
```

`kind`: `dividend_payment` | `meeting_participation`. `meeting_id` допускает `null`. `fetched_at` отдаётся наружу (решение Р-6) для индикатора свежести данных.

### Meeting

```json
{
  "id": 42,
  "ticker": "SBER",
  "short_name": "Сбербанк",
  "logo_url": "/static/logos/SBER.svg",
  "meeting_date": "2026-06-27",
  "meeting_type": "annual",
  "description": "О выплате дивидендов по итогам 2025 года",
  "dividend": {
    "period": "year",
    "amount_per_share": 33.30,
    "yield_percent": 8.4
  },
  "dsi": 82,
  "source_url": "https://disclosure.ru/...",
  "fetched_at": "2026-10-19T06:00:00Z",
  "record_date": {
    "record_date": "2026-07-10",
    "kind": "dividend_payment",
    "fetched_at": "2026-10-19T06:00:00Z"
  }
}
```

`meeting_type`: `annual` | `extraordinary`. Вложенный `record_date` — связанная отсечка `dividend_payment`, может отсутствовать (`null`) — ключевой кейс «собрание объявлено, дата отсечки ещё не известна». `description` допускает `null`. `logo_url` — логотип эмитента из `tickers` (ADR-0006), `null` — нет. Поля трассировки отдаются наружу (решение Р-6): `source_url` — ссылка на сообщение о собрании в источнике (фронтенд показывает её в деталях собрания S1.1); `fetched_at` — момент последнего сбора записи (индикатор свежести «обновлено N минут назад»).

`dividend` (ADR-0005) — дивидендные условия собрания; `null`, если они не раскрыты. `dsi` — индекс стабильности дивидендов эмитента, целое 0–100; `null`, если истории недостаточно. `dsi` одинаков для всех собраний одного тикера (берётся из `tickers.dsi`).

### DividendTerms

```json
{
  "period": "year",
  "amount_per_share": 33.30,
  "yield_percent": 8.4
}
```

- `period`: `year` | `half_year` | `quarter` | `null` — период, за который выплачиваются дивиденды.
- `amount_per_share`: число ≥ 0 или `null` — сумма на одну акцию, ₽.
- `yield_percent`: число ≥ 0 или `null` — дивидендная доходность к последней цене акции, %. **Вычисляется на чтении** как `amount_per_share / tickers.last_price × 100` с округлением до 0.1; в БД не хранится, клиент не пересчитывает.
- Объект `dividend` равен `null`, если неизвестны и период, и сумма; частично заполненный объект допустим.

### WatchlistItem (ответ)

```json
{
  "ticker": "SBER",
  "short_name": "Сбербанк",
  "logo_url": "/static/logos/SBER.svg",
  "threshold_days": 7,
  "created_at": "2026-10-19T12:00:00Z",
  "next_record_date": "2026-10-22",
  "next_meeting_date": "2026-10-23",
  "days_to_cutoff": 3,
  "status": "hot",
  "next_dividend": {
    "period": "quarter",
    "amount_per_share": 26.00,
    "yield_percent": 7.8
  },
  "dsi": 85
}
```

- `next_record_date` — ближайшая (на сегодня или позже) отсечка `dividend_payment`; `null`, если такой нет.
- `next_meeting_date` — дата собрания, связанного с `next_record_date` (через `record_dates.meeting_id`); `null`, если связь не установлена. Нужна для строки фактов S2 (ADR-0006).
- `days_to_cutoff` — целое число дней от текущей даты сервера до `next_record_date`; `null` вместе с `next_record_date`.
- `status` — вычисляемое на чтении, каноническая шкала (решение Р-4): `no_date` | `far` | `near` | `hot` | `critical` | `past`. Правила и пороги: [2026-10-19_правила-расчёта-статуса-сторожка_backend.md](./2026-10-19_правила-расчёта-статуса-сторожка_backend.md). Значений в БД нет.
- `next_dividend` — дивидендные условия ближайшей отсечки (та же схема `DividendTerms`); `null`, если отсечки или условий нет.
- `dsi` — DSI эмитента (0–100) или `null`.
- `logo_url` — логотип эмитента или `null` (ADR-0006).

### WatchlistCreate (тело POST /watchlist)

```json
{
  "ticker": "sber",
  "threshold_days": 14
}
```

- `ticker` — обязателен, строка, нормализуется (верхний регистр, trim). Должен существовать в `tickers`, иначе 404 `{"detail": "ticker not found"}`.
- `threshold_days` — необязателен, целое 1..365; при отсутствии — значение по умолчанию из конфигурации (`DIVCAL_WATCH_DEFAULT_THRESHOLD_DAYS`, 7).

## Эндпоинты

### GET /api/v1/tickers

Список тикеров с поиском и пагинацией.

Query: `q` (необязательный — подстрока, регистронезависимый поиск по `ticker` и `short_name`), `page`, `page_size`.

Ответ 200: `Page` из `Ticker`. Сортировка: `ticker` ASC. По умолчанию возвращаются только `is_active = true` (фильтрация на стороне бэкенда, параметром в MVP не управляется).

Пример: `GET /api/v1/tickers?q=сбер&page=1&page_size=20`.

### GET /api/v1/meetings

Календарь собраний акционеров (с вопросом о дивидендах).

Query: `from` (дата, по умолчанию — текущая дата сервера), `to` (дата, по умолчанию — `from + 90 дней`), `ticker` (необязательный фильтр), `page`, `page_size`. Валидация: `from <= to`, иначе 422.

Ответ 200: `Page` из `Meeting`, сортировка `meeting_date` ASC. Возвращаются собрания с `dividend_question = true` в интервале `[from, to]` включительно.

Пример: `GET /api/v1/meetings?from=2026-10-19&to=2026-12-31`.

### GET /api/v1/meetings/{id}

Карточка одного собрания по внутреннему идентификатору. Нужна фронтенду для восстановления модального окна деталей собрания по deep-link `?meeting=<id>` после перезагрузки страницы.

Ответ 200: `Meeting`. Ответ 404 — собрание не найдено: `{"detail": "meeting not found"}`.

Пример: `GET /api/v1/meetings/42`.

### GET /api/v1/record-dates

Календарь дат отсечки.

Query: `from`, `to` (аналогично /meetings), `ticker` (необязательный фильтр), `kind` (необязательный; по умолчанию `dividend_payment`), `page`, `page_size`.

Ответ 200: `Page` из `RecordDate`, сортировка `record_date` ASC.

### GET /api/v1/watchlist

Список сторожков пользователя с вычисленными `next_record_date`, `days_to_cutoff`, `status` (поля считаются на чтении).

Query: без обязательных. Пагинация применяется (конверт `Page`).

Сортировка (решение Р-7 ревью раунда 2 — канонический порядок списка S2 совместно с ui, см. §7 `design/ui/2026-10-19_индикация-сроков_ui.md`):

1. **датированные** сторожки (есть `next_record_date`) — по `next_record_date` ASC; это эквивалент зонального порядка `critical -> hot -> near -> far`;
2. затем сторожки со статусом `no_date` (`next_record_date IS NULL`, прошедших дат нет) — между собой по `ticker` ASC;
3. затем сторожки со статусом `past` (`next_record_date IS NULL`, есть прошедшие даты) — между собой по `ticker` ASC.

Группы 2 и 3 различаются только вычисленным статусом, поэтому на уровне запроса используются два прохода по NULL-блоку либо предварительный расчёт статуса с последующей сортировкой по ключу (`status_rank`, `next_record_date`, `ticker`).

Ответ 200: `Page` из `WatchlistItem`.

### POST /api/v1/watchlist

Добавить тикер в отслеживание. Тело: `WatchlistCreate`.

Ответы: 201 + `WatchlistItem` (создан); 200 + `WatchlistItem` (уже существовал — идемпотентный повтор, при переданном `threshold_days` значение обновляется); 404 (тикер не найден); 422.

### DELETE /api/v1/watchlist/{ticker}

Снять тикер с отслеживания.

Ответы: 204 (удалён) / 404 (сторожок для тикера отсутствует).

## Сводная таблица

| Метод и путь | Назначение | Успех |
|---|---|---|
| GET /api/v1/tickers | Список тикеров, поиск `q`, пагинация | 200 |
| GET /api/v1/meetings | Календарь собраний `?from&to&ticker` | 200 / 422 |
| GET /api/v1/meetings/{id} | Карточка собрания (deep-link модала деталей) | 200 / 404 |
| GET /api/v1/record-dates | Календарь отсечек `?from&to&ticker&kind` | 200 / 422 |
| GET /api/v1/watchlist | Сторожки + вычисленный статус | 200 |
| POST /api/v1/watchlist | Добавить сторожок (идемпотентно) | 201 / 200 / 404 |
| DELETE /api/v1/watchlist/{ticker} | Удалить сторожок | 204 / 404 |

## Примечание по именованию путей

Использованы пути `/meetings`, `/record-dates`, `/watchlist` (точнее системного черновика `design/system`, где фигурировали `/events`, `/watchers`). Именование зафиксировано настоящим контрактом; при расхождении с ранними системными документами истиной является этот файл (синхронизация — через ревью system-designer).

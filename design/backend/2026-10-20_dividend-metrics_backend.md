# Дивидендные метрики: расчёт доходности и DSI (backend)

Дата: 2026-10-20
Область: backend
Статус: проект, к согласованию system-designer (ADR-0005)

Назначение: зафиксировать хранение, расчёт и отдачу в API периода выплат, суммы на акцию, дивидендной доходности и DSI.

Основание: [ADR-0005](../system/adr/2026-10-20_adr-0005-dividend-metrics_system.md), [2026-10-19_database-schema_backend](./2026-10-19_database-schema_backend.md), [2026-10-19_api-contract_backend](./2026-10-19_api-contract_backend.md).

## 1. Термины и поля

| Термин | Поле БД | Поле API | Тип |
|---|---|---|---|
| Период выплат | `shareholder_meetings.dividend_period` | `dividend.period` | `year` / `half_year` / `quarter` / `null` |
| Сумма на акцию | `shareholder_meetings.dividend_per_share` | `dividend.amount_per_share` | `NUMERIC(12,4)` / `number` |
| Дивидендная доходность | не хранится | `dividend.yield_percent` | `number` / `null` |
| Цена для доходности | `tickers.last_price` | не отдаётся | `NUMERIC(18,4)` / `null` |
| DSI | `tickers.dsi` | `dsi` | `SMALLINT` 0–100 / `null` |

`dsi` — уровень эмитента, поэтому в DTO собрания дублируется для удобства карточки, но источник — строка `tickers`.

## 2. Дивидендная доходность

Формула на чтении:

```
yield_percent = round(dividend_per_share / last_price × 100, 1)
```

Правила:

- `last_price` — последняя цена акции из MOEX ISS (`fetch_tickers_moex.py`), обновляется ежедневно.
- Если `dividend_per_share IS NULL`, `last_price IS NULL` или `last_price <= 0` → `yield_percent = null`.
- Округление до одного знака после запятой (стандартное `round(x, 1)`).
- Доходность **не хранится** в БД: она всегда считается к текущей цене и меняется вместе с ценой. Это справочная величина «сколько даёт текущая выплата к текущей цене», а не историческая доходность на дату отсечки.
- Для прошедших собраний доходность также показывается к текущей цене; в UI это не помечается отдельно (осознанное ограничение MVP, см. §7).

Пример: `33,30 ₽ / 396,40 ₽ × 100 = 8,4%`.

## 3. DSI (индекс стабильности дивидендов)

### 3.1. Горизонт и агрегация

- Берутся последние **5 завершённых календарных лет** (для 2026 года — 2021–2025).
- Для каждого года суммируются все выплаты на акцию (для квартальных/полугодовых выплат — годовая сумма).
- Учитываются только выплаты с непустой суммой; годы без выплат дают DPS = 0.

### 3.2. Компоненты

- **Регулярность** `R` = (число лет с DPS > 0) / 5.
- **Стабильность** `S` = `1 − min(1, σ / μ)`, где `μ` — среднее годовых DPS, `σ` — стандартное отклонение по генеральной совокупности. Если `μ = 0`, то `S = 0`.
- **Отсутствие снижения** `N` = (число переходов «год к году», где DPS не снизился) / (общее число переходов). Переходы считаются между соседними годами горизонта, включая нулевые значения; если переходов нет, `N = 0`.

### 3.3. Формула

```
DSI = round(100 × (0.4 × R + 0.4 × S + 0.2 × N))
```

- Результат — целое 0–100. Округление — half-up.
- Если лет с выплатами меньше 3 → `dsi = null` (недостаточно истории; «0» зарезервирован за реально нестабильными выплатами).
- Если история есть, но все выплаты нулевые → `R = 0`, `S = 0`, `N` по переходам, DSI низкий.

### 3.4. Пример

Годовые DPS: 10, 12, 12, 14, 15.

- `R = 5/5 = 1`.
- `μ = 12,6`; `σ ≈ 1,74`; `S = 1 − 1,74/12,6 ≈ 0,862`.
- Переходы: 12≥10, 12≥12, 14≥12, 15≥14 → `N = 4/4 = 1`.
- `DSI = round(100 × (0,4 + 0,3448 + 0,2)) = round(94,48) = 94`.

### 3.5. Источник и обновление

- История выплат — MOEX ISS `/iss/securities/{secid}/dividends.json`.
- Расчёт выполняет `fetch_dividend_history_moex.py`; в БД пишутся только `tickers.dsi` и `tickers.dsi_updated_at`.
- Полная история выплат в БД MVP не хранится — это ограничение зафиксировано в ADR-0005; при необходимости истории появится отдельная таблица.
- Если источник недоступен, сохраняется прежнее значение DSI (не обнуляется).

## 4. Слои и ответственность

- `app/services/dividends.py`:
  - `compute_yield(amount_per_share, last_price) -> float | None`;
  - `build_dividend_terms(meeting, ticker) -> DividendTerms`;
  - `get_dsi(ticker) -> int | None` (читает снапшот, не пересчитывает).
- `app/services/calendar.py` и `app/services/watchlist.py` вызывают `dividends.py` при сборке DTO, чтобы не дублировать формулу.
- `app/repositories/*` отдают `last_price`, `dsi`, `dividend_*` вместе с собранием/сторожком (join), без N+1.
- Pydantic-схема `DividendTerms` — в `app/schemas/dividend.py`; поля Meeting/Watchlist ссылаются на неё.

## 5. Валидация и округление

| Правило | Значение |
|---|---|
| `dividend_per_share` | ≥ 0; отрицательное — ошибка нормализации, запись отбрасывается |
| `dividend_period` | только `year`/`half_year`/`quarter`/`null`; иное — `null` + WARNING |
| `yield_percent` | ≥ 0, один знак после запятой; `null` при отсутствии цены/суммы |
| `dsi` | целое 0..100; `null` при < 3 лет истории |
| `last_price` | > 0; иначе `null` |

## 6. Тесты

- Unit `compute_yield`: обычный случай, округление, `null` при отсутствии цены/суммы, цена ≤ 0.
- Unit DSI: 5 полных лет, пропуски, снижение выплат, все нули, 2 года истории → `null`, проверка округления half-up.
- API: `Meeting.dividend` и `dsi` в ответе; `WatchlistItem.next_dividend` для ближайшей отсечки; `null`-кейсы.
- Репозиторий: join цены и DSI не порождает N+1 (проверка количества запросов).

## 7. Ограничения и риски

- Доходность к текущей цене, а не к цене на дату отсечки; для прошедших событий величина справочная.
- DSI зависит от методики; сплиты и нестандартные выплаты не корректируются (MOEX отдаёт суммы как есть).
- DSI обновляется раз в сутки; между запусками скрипта значение может быть устаревшим (`dsi_updated_at` — для диагностики).
- Горизонт 5 лет и порог «≥ 3 лет» — параметры методики; вынесены в константы сервиса, не в UI.

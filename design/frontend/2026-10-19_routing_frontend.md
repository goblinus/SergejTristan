# Роутинг фронтенда (MVP)

Дата: 2026-10-19. Статус: проект, раунд 2 (доработка по ревью system-designer,
замечание frontend-3; решение Р-6).

Закрываемый вопрос: **соответствие навигации карте экранов ui** — маршруты
синхронизированы с `design/ui/2026-10-19_screens-map_ui.md` и
`design/ui/2026-10-19_navigation_ui.puml`.

Прежний маршрут `/meetings/:id` исключён (Р-6): детали собрания — модал
внутри календаря (`?meeting=<id>`), отдельной страницы и компонента
`MeetingPage` в MVP нет.

## 1. Карта маршрутов

| Путь | Имя | Компонент | Назначение |
|------|-----|-----------|-----------|
| `/` | — | — | Редирект на `/calendar` |
| `/calendar` | `calendar` | `CalendarPage` | Экран S1: календарь собраний и отсечек (точка входа) |
| `/me` | `me` | `WatchlistPage` | Экран S2: сторожки пользователя, поиск и добавление тикеров |
| `/:pathMatch(.*)*` | `not-found` | `NotFoundPage` | Catch-all 404 |

### 1.1. Query-параметры

| Маршрут | Параметр | Семантика |
|---------|----------|-----------|
| `calendar` | `meeting=<id>` | Открытый модал деталей собрания (S1.1, deep-link). Числовой id `Meeting`. Отсутствует/невалиден → модал закрыт |
| `me` | `ticker=<CODE>` | Префилл поля поиска тикера (переход из календаря по CTA «Отслеживать»). Одноразовый: после применения из URL удаляется |

Роутер читает query через `route.query`; запись — `router.replace`
(не `push`: открытие/закрытие модала и префилл не должны захламлять
историю). Отсутствие параметра `meeting` — единственное состояние «модал
закрыт»; закрыть модал = убрать параметр из URL (Esc, оверлей, крестик).

## 2. Конфигурация роутера

- История: `createWebHistory()` (history-режим HTML5; требование к хостингу —
  fallback на `index.html`, фиксируется при деплое).
- Ленивая загрузка страниц: `component: () => import('@/pages/…')` для
  `WatchlistPage` и `NotFoundPage`; `CalendarPage` — в основном чанке
  (точка входа).
- Редирект: `{ path: '/', redirect: { name: 'calendar' } }`.
- `scrollBehavior`: к началу страницы при переходе между маршрутами;
  `savedPosition` для «назад». Изменение только query (`?meeting=`) скролл
  не сбрасывает (модал поверх сохранённого списка).
- Валидация `?meeting=<id>`: `Number(route.query.meeting)`, не целое
  положительное → параметр удаляется (`router.replace`), модал не
  открывается. Валидация `?ticker=`: trim/UPPER, пустое → параметр удаляется.

```ts
// router/index.ts (скелет, контракт, не реализация)
const routes: RouteRecordRaw[] = [
  { path: '/', redirect: { name: 'calendar' } },
  { path: '/calendar', name: 'calendar', component: CalendarPage },
  { path: '/me', name: 'me',
    component: () => import('@/pages/WatchlistPage.vue') },
  { path: '/:pathMatch(.*)*', name: 'not-found',
    component: () => import('@/pages/NotFoundPage.vue') },
];
```

## 3. Навигация в UI

- Десктоп: `layout/AppHeader` (C-01) — вкладки «Календарь» → `calendar`,
  «Мои сторожки» → `me`. Активный пункт подсвечивается по имени маршрута
  (не по `path` — имя стабильнее при рефакторинге путей).
- Мобильная ширина (≤640px): та же навигация в `layout/BottomNav` (C-02),
  пункты те же: «Календарь» (`calendar_month`), «Мои сторожки»
  (`notifications_active`).
- Все переходы внутри приложения — только через именованные маршруты:
  `router.push({ name: 'me' })`. Строковые пути в коде запрещены
  (исключение — определение самих маршрутов в `router/index.ts`).
- Из карточки собрания (`MeetingCard`, S1) — не переход, а модал:
  `router.replace({ query: { ...route.query, meeting: id } })`.
- CTA «Отслеживать» на карточке — переход `router.push({ name: 'me',
  query: { ticker } })` с префиллом поиска (сценарий 3 карты экранов ui).

## 4. Защита от несуществующих маршрутов

1. Catch-all `/:pathMatch(.*)*` → `NotFoundPage` (HTTP-статус в SPA не
   выставляется; страница визуально сообщает об ошибке).
2. `NotFoundPage` содержит текст «Страница не найдена» и ссылку
   «Перейти к календарю» (`calendar`).
3. Случай «маршрут валиден, но ресурс не найден» (открыт
   `/calendar?meeting=999999`, бэкенд ответил 404 на `GET /meetings/{id}`):
   модал показывает встроенное состояние «Собрание не найдено» с кнопкой
   закрытия; закрытие удаляет `?meeting` из URL. Отличается от catch-all
   тем, что сам URL остаётся валидным.

## 5. Что не включаем в MVP

- Guards авторизации (нет авторизации).
- Отдельный маршрут карточки собрания/эмитента — заменён модалом (Р-6).
- Вложенные маршруты и layouts-уровня выше одного `App.vue`-каркаса.
- Хлебные крошки — два экрана не требуют.

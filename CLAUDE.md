# Дивидендный календарь

Выпускная работа практического курса по вайб-кодингу на Claude Code.

## О проекте

Автообновляемый сервис для непрофессиональных личных инвестиций на российском фондовом рынке. Пользователь выбирает тикеры Московской биржи и отслеживает приближение даты дивидендной отсечки («сторожок»).

Функциональность MVP:
- список тикеров Московской биржи;
- календарь собраний акционеров, на которых решается вопрос о выплате дивидендов;
- хранение дат дивидендной отсечки (дата закрытия реестра) перед собранием;
- «сторожок» на дату отсечки для выбранных тикеров;
- страница пользователя для выбора отслеживаемых тикеров.

Состав сервиса:
- **Фронтенд** — JavaScript/TypeScript, Vue.js 3, тёмная Material-тема;
- **Бэкенд** — Python, SQLAlchemy, Pydantic (uv для зависимостей);
- **База данных** — хранилище информации;
- **Скрипты сбора данных** — сбор сущфактов из официальных источников (moex.com, disclosure.ru и т.п.), нормализация и сохранение в БД.

## Структура проекта

- `design/system/` — верхнеуровневая архитектура и ADR (system-designer);
- `design/backend/` — спецификации бэкенда: схема БД, API-контракты, модули (backend-designer);
- `design/frontend/` — спецификации фронтенда: компоненты, состояние, роутинг (frontend-designer);
- `design/ui/` — макеты, UI-kit, UX-сценарии (ui-designer);
- `backend/` — реализация бэкенда (backend-developer);
- `frontend/` — реализация фронтенда (front-developer).

## Субагенты (.claude/agents/)

- **system-designer** (opus) — верхнеуровневая архитектура; ревью и согласование спецификаций дизайнеров; разрешение противоречий; постановка задач на доработку.
- **backend-designer** (sonnet) — архитектура бэкенда; производственный код не пишет.
- **frontend-designer** (sonnet) — архитектура фронтенда; производственный код не пишет.
- **ui-designer** (sonnet) — визуальный дизайн и UX; производственный код не пишет.
- **backend-developer** (sonnet) — реализация бэкенда в `backend/`.
- **front-developer** (sonnet) — реализация фронтенда в `frontend/`.

Порядок работы: спецификации готовят дизайнеры → system-designer проверяет и согласовывает → разработчики реализуют только согласованные спецификации. Противоречия между областями разрешает только system-designer.

## Технологический стек

- **Бэкенд:** Python, uv, SQLAlchemy, Pydantic;
- **Фронтенд:** JavaScript/TypeScript, Vue.js 3 (Composition API);
- СУБД, веб-фреймворк, сборщик и прочие решения — через ADR в `design/system/adr/`.

## Правила работы

- Перед изменением файлов проекта — запрашивать подтверждение у владельца.
- Перед установкой новых инструментов и зависимостей — запрос разрешения.
- Именование создаваемых файлов: `ГГГГ-ММ-ДД_название-файла_тип.расширение`, где `тип` — имя папки (`docs`, `backend`, `frontend`, `ui`, `system` и т.п.). Пример: `2026-09-24_расчет-вклада_docs.csv`.
